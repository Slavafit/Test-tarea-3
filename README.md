# Snapbuild — дополнение существующего лендинга

Тестовое задание на React + Vite: воспроизвести ключевые части действующего лендинга [snapbuild.ru](https://snapbuild.ru/) и встроить пять новых секций так, чтобы они воспринимались как части одной дизайн-системы. Backend по условиям не требуется; асинхронные данные и отправка формы имитируются на клиенте.

## 1. Опубликованная версия

[https://slavafit.github.io/Test-tarea-3/](https://slavafit.github.io/Test-tarea-3/)

Исходный код: [github.com/Slavafit/Test-tarea-3](https://github.com/Slavafit/Test-tarea-3)

## 2. Локальный запуск

Требуется Node.js 20 или новее.

```bash
npm install
npm run dev
```

Production-сборка и локальная проверка:

```bash
npm run build
npm run preview
```

## 3. Стек

- React 19;
- Vite;
- JavaScript;
- обычный CSS без UI-kit и CSS-фреймворков;
- локальные JSON-файлы и service layer;
- GitHub Actions + GitHub Pages.

## 4. Пять новых секций

1. **Кейсы использования** — вкладки «Маркетинг / Дизайн / Продажи / Продукт». Данные вынесены в JSON и получаются асинхронно через `useCasesService`.
2. **Результат в цифрах** — крупные продуктовые метрики, основанные на позиционировании исходного сайта.
3. **Отзывы** — JSON → service layer → React; предусмотрены состояния `loading`, `error`, `data` и переключение отзывов.
4. **Тарифы** — три варианта с работающим переключателем «Месяц / Год» и пересчётом стоимости.
5. **Форма заявки** — обязательные поля, проверка email, сообщения об ошибках, `loading`, mock submit и состояние успеха.

Секции встроены в исходный сценарий страницы, а не собраны отдельной группой внизу.

## 5. Как анализировалась стилистика

Действующая версия Snapbuild исследовалась в браузере: сравнивались computed styles, размеры контейнеров, типографика, фон, кнопки, карточки, радиусы, интервалы и поведение секций на разных экранах.

Зафиксированные параметры:

- шрифт `TT Commons Pro`, начертания 300–700;
- основной фон `#F5F5F6`;
- ширина контента около `1194px`;
- H1 до `76px`, H2 до `52px`;
- белые карточки и радиусы преимущественно `16px`;
- чёрные CTA-кнопки;
- градиентный финальный CTA;
- минимальное применение дополнительных цветов.

Ключевые шрифты, логотип и hero-изображение хранятся локально, чтобы результат не зависел от внешней загрузки на GitHub Pages.

## 7. Адаптив и доступность

Интерфейс проверен на ширинах 1280+, 768 и 375 px. На мобильном используются меню, горизонтально прокручиваемые табы и таблица, одноколоночные карточки и форма. Горизонтального переполнения страницы нет.

Добавлены семантические элементы, `label`, `aria-label`, `aria-selected`, `aria-invalid`, управление с клавиатуры нативными кнопками и поддержка `prefers-reduced-motion`.

## 8. Что намеренно не реализовано

- реальная отправка формы и хранение заявок — backend не требовался;
- полноценная CMS и авторизация;
- все анимации и каждый декоративный эффект production-версии Snapbuild;
- полное копирование всех материалов исходного сайта.

Цель — воспроизвести ключевой интерфейс и аккуратно продолжить его новыми секциями, а не создать зеркало сайта.

## 9. Что можно улучшить дальше

- разбить секции на отдельные файлы и добавить Storybook;
- добавить unit-тесты сервисов и компонентов, E2E-тест формы;
- подключить настоящий REST API без изменения UI-компонентов;
- добавить оптимизированные локальные версии всех иллюстраций;
- провести отдельный accessibility-аудит и Lighthouse-проход.

## 10. Использование AI-инструментов

AI использовался как помощник для анализа структуры исходного сайта, восстановления дизайн-токенов, подготовки React-компонентов, CSS, mock-данных, проверки адаптива и README. Результат проверялся вручную в браузере и production-сборкой Vite.

## Архитектура данных

```text
src/data/*.json
       ↓
src/services/*Service.js
       ↓
React-компонент
       ↓
loading / error / data
```

Замена JSON настоящим API потребует изменения реализации сервиса, а не компонента.

## GitHub Pages

Workflow `.github/workflows/deploy.yml` автоматически собирает и публикует `dist` после каждого push в `main`. Базовый путь `/Test-tarea-3/` задан в `vite.config.js`.
